# brain-plan：代码事实核实 + 展开计划

规则权威：`brain/rules.md`。格式：读 `brain/formats.md` §2（trues）与 §3（plans）。前置：decisions.md 中已有确认的决策条目（提供锚点时间戳）。

## 步骤

1. **核实代码事实**：用 codegraph_explore 完整阅读相关代码（调用路径、影响范围、字段/函数/配置）；图谱未覆盖的当场实测（读文件、跑命令），不凭记忆。产出 `brain/trues/trues-<时间戳>.md`（§2）：
   - 只记事实：文件、函数、字段、调用关系、当前行为，每条附路径/行号；
   - 建议与方案一律不写；无法核实的列入「未核实项」，明说未核实。
2. **检查未决项**：存在未决设计取舍或阻塞性未核实项 → 先调用 brain-grill 拍板；无 → 直接进入下一步。
3. **产出计划**：写 `brain/plans/plans-<时间戳>.md`（§3）：
   - 每个实施步骤注明所依据的 trues 事实条目；无事实依据的步骤不得出现；
   - 验收标准写成可勾选、可验证的清单。
4. **一并展示两份文档**，等用户确认后进入开发；确认后回填 decisions.md 条目的「事实」「计划」链接，并按仓库约定提交 git。
5. 用户对事实纠错 → 修 trues → 相应改 plan → 再次展示。

## 执行期与变更

- 按计划开发，验收标准完成一项勾一项；状态冲突以 decisions.md 为准。
- 计划变更：改文档本身，文末追加变更记录（日期 + 一句话）；重大变更需用户确认。
- 开发完成后建议运行 brain-verify 核查。
